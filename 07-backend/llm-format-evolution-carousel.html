Step 01 • The Beginning

Plain Text Outputs

Early LLM integrations simply prompted models for raw natural language text. Excellent for human reading, but problematic for software pipelines.

How It Works

Unstructured Completion

The model responds in freeform prose (e.g., "The weather in Berlin is 4 degrees with snow, and rain chance is 80%"). The caller gets a continuous stream of tokens formatted as human sentences.

The Integration Bottleneck

Why Plain Text Fails in Code

Building production backend software requires deterministic data shapes, not unstructured conversational paragraphs.

Parsing Fragility

Brittle Regex Hacks

Extracting variables from prose requires complex regular expressions. Minor phrasing variations from the LLM instantly crash downstream backend parsers.

No Type Guarantees

Schema Inconsistency

Plain text offers zero structural validation. Arrays, booleans, and numeric types are returned as arbitrary words without deterministic types.

Step 02 • Structured Data

JSON Standardization

To make LLMs developer-friendly, OpenAI and Anthropic introduced JSON Mode & Structured Outputs to enforce typed schemas.

The JSON Advantage

Deterministic Integration

LLMs generate valid JSON matching strict JSON Schema definitions. Downstream code parses responses natively with JSON.parse() into strongly-typed TypeScript or Python objects.

The Token Overhead

Why JSON Burns LLM Tokens

JSON was designed for human readability and web APIs, not for token-metered LLM context windows.

Syntax Bloat

Punctuational Overhead

Every quote "", colon :, comma ,, brace {}, and bracket [] is tokenized, consuming costly context window budget.

Key Repetition

Array Schema Waste

In an array of 100 objects, JSON repeats every key name (e.g. "day", "temp", "condition") 100 times, wasting thousands of tokens.

Step 03 • Token-Optimized Format

Meet TOON Format

TOON (Token-Optimized Object Notation) is a compact, schema-declared data format designed specifically to minimize LLM token usage.

1

Schema-Header Declaration

Arrays declare their schema fields ONCE in the header: forecast[3]{day,temp{min,max},condition}.

2

Quote-Free & Minimal Punctuation

Removes quotes, braces, and repetitive keys. Values are streamed in clean tabular rows separated by simple commas.

3

Massive Token Reduction

Cuts prompt and completion tokens by over 60% while maintaining 100% loss-less structured data parsing.

Under the Hood

3 Mechanisms of TOON

How TOON strips out token redundancy without losing data types or structural validation.

A

Header-Declared Array Schemas

Instead of repeating "day", "temp" on every row, TOON declares forecast[3]{day,temp{min,max},condition} once in the header.

B

Quote-Free Literal Values

Strings and numbers are emitted directly without surrounding quotes, saving 2 tokens per field value.

C

Comma Tabular Value Rows

Row values are comma-separated (e.g. Mon,-2,4,snow,80), enabling fast tokenization without JSON syntax bloat.

Decision Matrix

When to Use Which Format

Choosing the optimal payload format based on your system architecture and context window constraints.

Plain Text

Conversational UI

Best for user-facing chat apps, freeform summaries, and creative writing prompts where code parsing isn't required.

JSON Format

Web REST APIs

Best for standard client-server web APIs, webhooks, and single-object LLM responses with few array items.

TOON Format

High-Volume LLM & RAG Pipelines

Best for structured LLM prompts, multi-item array data, RAG context injection, and agent execution loops where cutting token costs and latency by 60%+ is critical.
